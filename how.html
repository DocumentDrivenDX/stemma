The research cycle

One round, step by step

  1. Start a project

    You might say “Start a Stemma project in this folder.”

    Claude creates a few project files and overwrites nothing.

    One of them, rules.md, holds your standing rules, such as how to spell a place name. Claude is instructed to read it at the start of each session.

  2. Gather your sources

    You might say “Add a source record for this book, taking the details from its title page.”

    Claude writes a record of the work and tells you where each detail came from. It is instructed never to invent one.

  3. Capture your sources

    You might say “Capture this PDF as my copy of that source. I downloaded it from the library today.”

    Stemma turns it into text files in your project, one for each page, with where and when you got it. A digital fingerprint ties them to the exact original, which is not added to the project.

    You can record more than one place the original can be had, such as its web address and a copy in a web archive. Only a file with the same fingerprint counts as that original.

    It reads the text a PDF already contains, and reads EPUB, web pages, Word documents, Markdown, Project Gutenberg and plain text files. It cannot read words from a picture of a page: you supply that text, made by a recognition tool or typed.

    Anyone who can read your project can read these files, so publishing it publishes them. You can note that material is unpublished or restricted by a community. These notes inform you; they stop nothing.

  4. Check the text and page numbers

    You might say “Compare the text with the original and look at the page numbers.”

    Stemma proposes page numbers only where the numbers printed on the pages support them. A book with no pages is cited by chapter or paragraph.

    It can convert the original again to show that the text still matches. For text a computer recognized, you can compare it with another reading and note what you looked at. None of that is required.

  5. Write, and cite

    You might say “Find where that book discusses atolls, and cite the passage I choose.”

    When you choose a passage, a script copies its words and page, so nobody retypes them.

    A citation you already have is recorded exactly as you wrote it, with its sentence, source, page and any quotation.

    You can ask to see a few pages while you write. They are marked as text quoted from the source, which may contain errors.

  6. Check

    You might say “Check the project and explain what is open.”

    The whole project is checked. Claude explains what is wrong, shows the evidence, says why it matters and suggests what to do.

    A check that cannot be done is reported as could not check. It never counts as a pass.

    What nothing shows or contradicts, such as a source not compared with any catalogue, is listed as coverage. It is not a problem and asks nothing of you.

  7. Decide, and go round again

    You might say “I have a better scan of this book. Replace the old one.”

    You choose what to fix. When a source is replaced, you see what relied on the old one. This version cannot note that you have looked again, so those items stay listed.

    Ask Are any of my source files missing or changed? to find files that have gone missing or been edited.

What Stemma reads, and how each is cited

Much of what you read on a technical subject has no page numbers. A paragraph number is counted through Stemma’s copy of a page: it is not printed on the page itself, and another copy of the same address may count differently. That is one reason the text you cite is kept in your project.

  • PDF paper or manual → Printed page number

    One file for each page. Page numbers are taken from those printed on the pages, where they support them. A passage on a page with no established number gets no page.

  • Web page you saved → Paragraph or chapter

    Documentation, release notes and articles usually have no pages: a passage is cited by paragraph number, or by chapter where the headings number chapters. A page that marks its own page numbers keeps them.

  • EPUB book → Page where it is marked

    Cited by page where the book marks its page numbers, and otherwise by chapter or paragraph.

  • Word document → Never a page number

    A Word file has no fixed pages, so it is cited by chapter or paragraph. To cite pages, export a PDF and capture that.

  • Markdown or plain text → Chapter or paragraph

    This includes Project Gutenberg texts. Plain text that marks its page breaks is kept page by page instead.

  • Scan or page images → Text you supply

    Stemma cannot read words from a picture of a page. You supply them, from a recognition tool or typed, page by page.

Claims, and what bears on them

A thesis and the claims under it can be recorded with how sure you are and why, and linked to notes on passages. Each link says whether the note supports the claim, supports it in part, qualifies it, contradicts it or only gives context, so evidence against you is kept beside evidence for you. A check lists a recorded claim that lacks a note, a level of confidence or a reason. It does not judge whether a note supports a claim.

  • Thesis (confidence: medium)

    PostgreSQL 18 is a sound default primary datastore for a web application while the application’s writes fit comfortably on one primary server and that server’s upkeep is attended to. The limits to plan for follow from that single write primary: a process for each connection, row versions and transaction IDs that vacuum has to keep reclaiming, and replication that does not divide writes.

  • Docs: architecture → Supports: a process each → Thesis

    Each client connection is served by its own server process, forked for it. This note supports the thesis. It rests on one passage of “Architectural Fundamentals”.

  • Docs: replication → Supports: one writer → Thesis

    PostgreSQL does not offer synchronous multimaster replication; in partitioning, only one server can modify each set. This note supports the thesis. It rests on 2 passages of “Comparison of Different Solutions”.

  • Release notes: 19 → Qualifies: version 19 → Thesis

    The version 19 release notes announce online table repacking and a command for reading one’s own writes on a standby. This note qualifies the thesis. It rests on 2 passages of “Release 19”.

  • Pavlo and Zhang, 2023 → Contradicts: storage → Thesis

    Pavlo judges the multiversion implementation the worst among the widely used relational systems he names. This note contradicts the thesis. It rests on one passage of “The Part of PostgreSQL We Hate the Most”.

The report

Ask Claude to build the report. Each quotation is copied from your source’s text through the passage you chose, so nobody retypes it, and citations are written in Chicago notes-and-bibliography style from your source records.

  • Your manuscript → Build the report

    The report's own words. The build never changes them.

  • List of quotations → Build the report

    Which passages the report quotes, and where.

  • Passage records → Build the report

    The words and place of each quotation, as a script copied them.

  • Source records → Build the report

    The details of each work, from which its citations are written.

  • Build the report → Report with footnotes

    Markdown and a typesetting file, and a PDF if you ask. Each note gives a quotation, then its citation.

  • Build the report → Verification table

    A table, kept apart from the report, of where each quotation was copied from and how it was checked, as recorded.

  • Build the report → Evidence ledger

    What is recorded behind each sentence. It does not judge whether a sentence is supported.

What going round looks like

In the demo, one project is checked four times. The numbers fall as things are fixed, added and looked at.

Where your material lives

Words used here

Record
A small plain file about one thing: a source, where its original came from, a passage or a citation.
Original
The file the text was made from, such as a PDF. It is not added to the project.
Source files
The text of a work, kept in your project: one file for each page, or for each section where there are no pages.
Passage
A piece of a source chosen by its place. A script copies its words and page.
Page label
The number printed on a page, where it could be established.
Note
A short extract or paraphrase that names the passages it rests on, or a comment of your own.
Claim
Something your report asserts, recorded with how sure you are and why. Notes can support it, support it in part, qualify it, contradict it or give its context.
Finding
One thing a check reports, with its evidence and a suggestion.
Could not check
Something needed was missing, so there is no answer yet.
Coverage
What a report covered by other means, or did not cover, and what it saw in an original. It is not a list of things to do.
Checked clean
The checks found nothing open. It does not mean the book is correct.
Unreviewed, not admitted
A report counts cited items that nobody has reviewed, and sources you have not accepted into your project. The count is information, not a finding.
