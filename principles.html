Principles

How Stemma decides between two reasonable options.

These are design commitments. Several describe parts that are not built yet. This page is generated from the project's principles document.

  1. Tools and reports, not gates and approvals. Stemma finds problems and explains them. It never stops the author from writing, or asks them to verify or approve something before they can continue. Review and attestation happen out of line, when the author chooses. Every finding says what is wrong, shows the evidence, says why it matters and suggests what to do, in plain language; unexplained noise is a Stemma defect. This changes decisions when a block, a required confirmation, or one more warning would seem the safe choice.
  2. No source, no citation. A citation rests on a source record and a stored copy. The assistant never invents one, and a citation without them is shown as unchecked. This changes decisions when a faster path would let an assistant's word look like a checked reference.
  3. Scripts verify, models propose. A scripted check never depends on a model's judgment. A model result counts only as a record that a script checks for presence, currency, and findings. This changes decisions when a model check would be simpler than a deterministic one.
  4. The author decides. The assistant drafts, searches, and files, and marks what it wrote as unreviewed. Interpretation, structure, theoretical framing, method, and disclosure stay with the author. This changes decisions when automation could settle an interpretive question.
  5. Limits are stated. "Checked clean" means only that the checks found nothing open. Review marks, annotations, confirmations, and model verdicts are records, not proof, and the product says so. This changes decisions when a stronger-sounding claim would outrun what a check shows.
  6. Plain text and hashes. Prefer files that diff, merge, and survive a change of tool, and identify binaries by content hash. This changes decisions when a proprietary or opaque format would be easier today.
  7. One source of truth. Notes, claims, citations, maps, and the typeset book derive from the same record files. This changes decisions when a second writable copy would save a build step.
  8. Reproducible with the same inputs. Someone with the project, the sources they have rights to, and the same tool versions gets the same scripted check results. This changes decisions when a result depends on a local setting, a network call, or an unrecorded step.
  9. Respect what is not yours to share. Rights, permissions, restricted locations, and community data limits shape the corpus and what goes into outputs that leave the project. Material that may not be sent to a language model does not belong in a project that uses a hosted one; Stemma does not filter it by source. This changes decisions when completeness conflicts with permission.
  10. Deliverable over machinery. Ship what authors use. Bound the process around it, freeze it, and deliver; reuse a family tool before building a new one. Real defect checks stay. This changes decisions when new checks, reviews, or automation would delay working behavior without catching a material defect.
