What gets checked

18 checks, what each looks at, and what passing it does not tell you.

Each check answers pass, fail or could not check (the tool writes unverifiable). Nothing is ever blocked. A pass covers only what that check reads. You do not need the names in small type; they are how a report refers to a check.

The checks

  • Do you hold what you cite?
  • Is each source's text complete and unchanged?
  • Does the text still match its original?
  • Do the page numbers make sense?
  • Do footnotes and their markers pair up?
  • Is the quotation in the source?
  • Is the quotation on the page you cite?
  • Is the cited page really there?
  • Is your figure in the source?
  • Do the details match the work itself?
  • Do the details match a library catalogue?
  • Does each identifier lead to the right work?
  • Which source does this citation mean?
  • Is every listed work cited?
  • Did something you relied on change?
  • Are the project files in order?
  • Is a location written where it should not be?
  • Does your project hold only text?
  • What is not checked

Do you hold what you cite? source.held

Each cited source needs its text in your project, and that text must be undamaged.

What a pass does not tell you: It does not compare the text with the pictures of the pages, or show that the source supports your sentence.

Is each source's text complete and unchanged? source.pages

No page or section may be missing, extra, out of order or edited without a record, and there should be as many pages as the original had.

What a pass does not tell you: Complete and unchanged files can still hold wrong text.

Exact wording: the full description and every message (9)

Each source file's manifest and its page or section files must agree: none missing, extra, out of order, unreadable or edited without being sealed, and as many pages as the original has.

Limits: It shows that the files are complete and unchanged, not that their text is right. The count of pages in the original is the one recorded at conversion.

  • part_missing

    A page or section file that the manifest lists is missing.

    Why it matters
    Every quotation and page check reads these files. A missing, reordered or changed part can hide or invent what the source says, so this source file is not used until it is sound.
    What to do
    Restore the file from git.
  • part_edited

    A page or section file differs from the digest its manifest records.

    Why it matters
    Every quotation and page check reads these files. A missing, reordered or changed part can hide or invent what the source says, so this source file is not used until it is sound.
    What to do
    If you meant to edit it, record the edit with `source seal <text id> --actor person:<name>`. Otherwise restore it from git.
  • part_unlisted

    A page or section file is in the source directory but not in its manifest.

    Why it matters
    Every quotation and page check reads these files. A missing, reordered or changed part can hide or invent what the source says, so this source file is not used until it is sound.
    What to do
    Remove the file, or convert the source again.
  • part_unreadable

    A page or section file cannot be read.

    Why it matters
    Every quotation and page check reads these files. A missing, reordered or changed part can hide or invent what the source says, so this source file is not used until it is sound.
    What to do
    Restore the file from git.
  • part_index

    A page or section file's place does not agree with its name or its manifest.

    Why it matters
    Every quotation and page check reads these files. A missing, reordered or changed part can hide or invent what the source says, so this source file is not used until it is sound.
    What to do
    Restore the files from git; their order is part of what is checked.
  • part_sequence

    The manifest does not list the pages or sections in sequence.

    Why it matters
    Every quotation and page check reads these files. A missing, reordered or changed part can hide or invent what the source says, so this source file is not used until it is sound.
    What to do
    Restore the manifest from git.
  • page_count

    The pages of the source file do not match the number of pages in the original.

    Why it matters
    Every quotation and page check reads these files. A missing, reordered or changed part can hide or invent what the source says, so this source file is not used until it is sound.
    What to do
    Restore the missing pages from git, or convert the original again. A source file that holds only some pages must say so.
  • part_invalid

    A source file's manifest or a part breaks the source file format, so its completeness could not be checked.

    Why it matters
    Every quotation and page check reads these files. A missing, reordered or changed part can hide or invent what the source says, so this source file is not used until it is sound.
    What to do
    See the record.valid finding and correct it.

    Why it matters

    What to do

Does the text still match its original? source.original

Each source's text must be tied to the original it was made from, and converting that original again must have given the same text.

What a pass does not tell you: It reads the recorded comparison, not the original. Converting again repeats any mistake already in the original's own text.

Exact wording: the full description and every message (4)

Each source file must be tied to an original that its source's upstream records name, and a recorded fresh conversion of that original must still apply and agree.

Limits: It reads the recorded comparison: it does not open the original. A conversion that agrees repeats any mistake already in the original's text layer.

  • original_not_upstream

    A source file was converted from an original that none of the source's upstream records names.

    Why it matters
    The chain from the original to your citation rests on the source file being what the original gives.
    What to do
    Check which original is right. Record its upstream (`ingest --plan`), or retire this source file.
  • conversion_differs

    A fresh conversion of the original does not give the committed text, after a person's corrections are undone.

    Why it matters
    The chain from the original to your citation rests on the source file being what the original gives.
    What to do
    Look at the differing readings. If a person edited the words, mark the change as a correction; otherwise restore the file, or convert the original again and retire this one.
  • comparison_stale

    The text or the tools changed after the last fresh conversion was compared, so it no longer says anything.

    Why it matters
    The chain from the original to your citation rests on the source file being what the original gives.
    What to do
    Run `source verify <text id> --original <file>`, or `ingest` with the originals.
  • check_error

    The check itself failed while running, so this was not checked.

    Why it matters
    This is a defect in Stemma, not a pass.
    What to do
    Report the defect together with the Stemma version.

Do the page numbers make sense? source.labels

Printed page numbers should run on from page to page, and agree with the numbers printed on the pages.

What a pass does not tell you: Where every page of the original is held and the text plainly runs on across a jump, the report records it as something seen in the original. Otherwise a jump stays open: it may be a missing leaf or a wrong label.

Exact wording: the full description and every message (5)

Printed page labels in a source file must run on sensibly, and must agree with any page number marked on the page.

Limits: Pages with no established label are left out. A finding may be a misprint or a missing leaf in the original: look at the page.

  • label_repeated

    Two pages in sequence carry the same printed label.

    Why it matters
    Citations name printed pages. A wrong page label makes a wrong page reference pass, or a right one fail.
    What to do
    Look at the page images. Correct the page map (`source label`), or leave a page without a label if its number is not established.
  • label_backwards

    Printed page labels go backwards.

    Why it matters
    Citations name printed pages. A wrong page label makes a wrong page reference pass, or a right one fail.
    What to do
    Look at the page images. A second numbering bound into one file can do this: label only the pages of the work you cite.
  • label_jump

    Printed page numbers advance by more than the pages do, as when pages are missing from the original or a label is wrong.

    Why it matters
    Citations name printed pages. A wrong page label makes a wrong page reference pass, or a right one fail.
    What to do
    Nothing in the text shows that the pages run on. If leaves are missing from your copy, capture a complete one; if a label is wrong, correct the page map (`source label`).
  • folio_differs

    A page number printed on a page differs from the label recorded for that page.

    Why it matters
    Citations name printed pages. A wrong page label makes a wrong page reference pass, or a right one fail.
    What to do
    Look at the page image and correct whichever is wrong.

Do footnotes and their markers pair up? source.footnotes

Where footnotes could be told apart, each marker should have its note and each note its marker.

What a pass does not tell you: It says nothing about pages whose footnotes could not be determined, which includes most scans.

Exact wording: the full description and every message (3)

Where a source file marks footnotes, each marker has its note and each note its marker.

Limits: It applies only to notes the conversion could determine. It says nothing about pages whose notes are marked as undetermined.

  • marker_without_note

    A note marker in the text has no note on its page or section.

    Why it matters
    A marker without its note, or a note without its marker, suggests text was lost or put in the wrong stream in conversion.
    What to do
    Compare the page with the original. The note may continue from or onto another page, or the conversion may have lost it.
  • note_without_marker

    A note has no marker in the text of its page or section.

    Why it matters
    A marker without its note, or a note without its marker, suggests text was lost or put in the wrong stream in conversion.
    What to do
    Compare the page with the original. If the note continues from an earlier page, mark its block continued.

    Why it matters

Is the quotation in the source? quote.present

Each recorded quotation is looked for in the source's text. Differences in line breaks and spacing, and a few other quirks of printed and scanned text, are allowed. A close but different passage is shown next to your quotation.

What a pass does not tell you: A pass means agreement with the source's text, which can be wrong.

Exact wording: the full description and every message (8)

Each quotation held by a citation record must be in the text of the cited source's files, apart from six harmless differences: white space and line breaks, soft hyphens, Latin ligatures, two Unicode spellings of the same characters, straight against curly quotation marks of the same level, and a word the text splits with a hyphen at a line end. Captured passages, note extracts and the quoted words of anchored passages are compared too. A close but different passage is shown beside the quotation.

Limits: A pass is agreement with the source text, which can be wrong, especially where it comes from character recognition. The cited page is tested by quote.page. Joining a line-end hyphen can pass a quotation that drops a hyphen belonging to the word; the report names each join. It does not read manuscript files.

  • near_match

    A quotation is not in the source's text as written. A passage close to it is; both are shown.

    Why it matters
    Readers take quoted words to be the source's own. Words the source does not hold misreport it.
    What to do
    Compare the two texts, and look at the page itself, since converted or recognized text can be wrong. If your quotation is wrong, capture the passage by its address so the words are copied. An omission, an added word, a change of capitals or punctuation, an ellipsis or a bracketed edit all count as differences.
  • absent

    A quotation was not found in the source's text.

    Why it matters
    Readers take quoted words to be the source's own. Words the source does not hold misreport it.
    What to do
    Find the words (`passage find`) and capture them, or remove the quotation marks if these are your words or a paraphrase. If the page does hold these words, the source text is wrong there, or it is a different edition: record that, or capture the copy you quoted.
  • passage_differs

    A passage record no longer matches the words at its address.

    Why it matters
    Readers take quoted words to be the source's own. Words the source does not hold misreport it.
    What to do
    Do not edit the record's words. Capture the passage again from the source text and retire this one.
  • citation_differs

    A citation made from a passage no longer says what the passage says: its quotation or locator was changed.

    Why it matters
    Readers take quoted words to be the source's own. Words the source does not hold misreport it.
    What to do
    Add the citation again from the passage, so that both are copied, and retire this one.
  • text_unavailable

    A quotation could not be compared: the text of its source cannot be used here.

    Why it matters
    Until the quotation can be compared with the source's text, it is unchecked.
    What to do
    See the source.held and source.pages findings, then capture or repair the source's text.
  • poor_quality

    A quotation was not found, but the only text is marked poor, so this does not show that the source lacks it.

    Why it matters
    Until the quotation can be compared with the source's text, it is unchecked.
    What to do
    Look at the page itself, or capture a better text.
  • anchor_not_found

    A note extract could not be compared: none of the passages it is anchored to can be found in the source text.

    Why it matters
    Until the quotation can be compared with the source's text, it is unchecked.
    What to do
    See the findings on its passages, and anchor the note to a passage that is in the text.
  • check_error

    The check itself failed while running, so this was not checked.

    Why it matters
    This is a defect in Stemma, not a pass.
    What to do
    Report the defect together with the Stemma version.

Is the quotation on the page you cite? quote.page

The quoted words must be on the page, or in the chapter or paragraph, that your citation gives.

What a pass does not tell you: It relies on the page numbers established for the source. Where a page has none, it says it could not check.

Exact wording: the full description and every message (4)

Where a citation gives a quotation and a locator, the quoted words must be on that page, or in that chapter or paragraph.

Limits: It relies on the page labels in the source files. Where a part has no label, it reports that it could not check.

  • wrong_page

    The quoted words are in the source, but not where the citation says.

    Why it matters
    A reader who turns to the cited place and does not find the words cannot check them.
    What to do
    Look at the place found, and correct the citation's locator, ideally by citing a captured passage so that the locator is copied.
  • partly_on_page

    The quotation runs beyond what the citation names, for example over a page break.

    Why it matters
    A reader who turns to the cited place and does not find the words cannot check them.
    What to do
    Cite every page the words lie on, as a captured passage does.
  • place_unknown

    Where the quoted words lie could not be compared with the locator: that part of the text has no such page label, chapter or paragraph.

    Why it matters
    A reader who turns to the cited place and does not find the words cannot check them.
    What to do
    Establish the page labels (`source pages`, `source label`) from what shows them, or cite a locator the source's text has.
  • check_error

    The check itself failed while running, so this was not checked.

    Why it matters
    This is a defect in Stemma, not a pass.
    What to do
    Report the defect together with the Stemma version.

Is the cited page really there? locator.extent

The page, or other pointer such as a chapter, must fall within what is recorded for the work or within what its text holds.

What a pass does not tell you: It only tests the range. It does not show that what you describe is on that page.

Exact wording: the full description and every message (7)

A citation's page or other locator must fall inside the extent recorded on the source or, for pages, folios, chapters and paragraphs, inside what the source files hold.

Limits: It tests range only, not that anything is on that page. Source files made from part of a work cover only that part. It reads citation records only.

  • outside_extent

    A citation's locator is outside the extent recorded for the work.

    Why it matters
    A page or other locator that is not in the work sends a reader nowhere, and is a common sign of an invented or mistyped citation.
    What to do
    Check the locator against the work and correct it. If the recorded extent is wrong, correct the source record.
  • outside_page_map

    A cited page, chapter or paragraph is outside those in your source files.

    Why it matters
    A page or other locator that is not in the work sends a reader nowhere, and is a common sign of an invented or mistyped citation.
    What to do
    Check the number against the source and correct it. If it is right, your source file holds only part of the work or leaves that page without a label.
  • page_not_mapped

    A cited page falls between labelled pages, on a page with no established label, so it could not be checked.

    Why it matters
    Until the locator can be compared with the work's pages or extent, a wrong one would go unnoticed.
    What to do
    Look at the page. If its number can be established, add it to the page map and run `source label`.
  • no_extent

    A locator could not be checked: no extent is recorded for it, and no source file has its numbering.

    Why it matters
    Until the locator can be compared with the work's pages or extent, a wrong one would go unnoticed.
    What to do
    For pages, label your source file's pages; a source with no pages cannot check a page number. For another kind of locator, record the work's extent on the source, taken from the work itself.
  • unparsable_locator

    A locator is not written in a form that can be compared with the work's pages or extent.

    Why it matters
    Until the locator can be compared with the work's pages or extent, a wrong one would go unnoticed.
    What to do
    Write it as the printed label, or as a range with both ends in full, such as 41-43. Otherwise check it by hand.
  • record_unreadable

    A locator could not be checked: a source file of this source cannot be read or is damaged.

    Why it matters
    Until the locator can be compared with the work's pages or extent, a wrong one would go unnoticed.
    What to do
    See the record.valid and source.pages findings, repair the source file, then run `check` again.
  • check_error

    The check itself failed while running, so this was not checked.

    Why it matters
    This is a defect in Stemma, not a pass.
    What to do
    Report the defect together with the Stemma version.

Is your figure in the source? number.present

A figure in a sentence that cites one source should appear in that source's text.

What a pass does not tell you: It finds the figure anywhere in the source, whatever it counts there. It does not read figures written as words.

Exact wording: the full description and every message (4)

A figure in a sentence that cites one source must be in that source's text.

Limits: It finds the figure anywhere in the source, not necessarily where cited or with the same meaning. Figures written as words are not read.

  • figure_absent

    A figure in a sentence that cites this source was not found in the source's text.

    Why it matters
    A figure attributed to a source that does not hold it misreports the source.
    What to do
    Find the figure in the source and correct the sentence, or move the figure to a sentence that does not attribute it to this source. A converted or recognized text can also be wrong: look at the page.
  • several_citations

    A sentence with a figure cites more than one source, so which one holds the figure could not be judged.

    Why it matters
    A figure attributed to a source that does not hold it misreports the source.
    What to do
    Nothing needs doing. A sentence that cites one source has its figures looked for there.
  • text_unavailable

    A figure could not be compared: the source has no usable text.

    Why it matters
    A figure attributed to a source that does not hold it misreports the source.
    What to do
    Capture or repair the source's text.

Do the details match the work itself? meta.source

Authors, title and date are compared with what the original states about itself and with the text of its title page.

What a pass does not tell you: Scanned text can garble a title page. A saved catalogue record that agrees then bears the detail out. With neither, the report says it was not covered; that is not a problem to fix.

Exact wording: the full description and every message (5)

A source record's title, authors, year and venue are compared with what its captured copy states about itself and with the text of its title page.

Limits: It applies to sources that have source files. A value that recognized text garbles is reported as not found, which a person can confirm by looking. It shows disagreement, not which side is right.

  • mismatch

    The source record disagrees with what the captured copy states about itself.

    Why it matters
    A reference with the wrong author, title or year points readers to the wrong work, and is a common sign of an invented or confused citation.
    What to do
    Compare both values with the title page of the work. Correct the record if it is wrong; if the copy is a different edition or a misdescribed file, capture the right one.
  • source_damaged

    The source's details could not be compared with a copy: its source file is damaged.

    Why it matters
    A reference with the wrong author, title or year points readers to the wrong work, and is a common sign of an invented or confused citation.
    What to do
    See the source.pages finding and repair the source file.
  • not_found_in_copy

    Some of the source's details are shown neither by the copy's title page text nor by a saved catalogue record, and nothing contradicts them.

    Why it matters
    A reference with the wrong author, title or year points readers to the wrong work, and is a common sign of an invented or confused citation.
    What to do
    Nothing needs doing: this is a limit of what was covered. A saved lookup or a copy with a clearer text would corroborate more. The author may also record what the title page shows (`review add --scope source_details`).
  • nothing_to_compare

    The source record has no title yet, so its details could not be compared with the copy.

    Why it matters
    A reference with the wrong author, title or year points readers to the wrong work, and is a common sign of an invented or confused citation.
    What to do
    Nothing needs doing. Once a title is recorded, it is compared.
  • check_error

    The check itself failed while running, so this was not checked.

    Why it matters
    This is a defect in Stemma, not a pass.
    What to do
    Report the defect together with the Stemma version.

Do the details match a library catalogue? meta.resolver

Authors, title and date are compared with catalogue records saved in your project. A body filed under its parent body, and a part entered after the title of its collection, count as the same name or title.

What a pass does not tell you: A catalogue can be wrong, or describe another edition or a whole set of volumes. A source not compared with any catalogue is reported as not covered, not as a problem.

Exact wording: the full description and every message (5)

A source record's title, authors, year and venue are compared with saved catalogue lookups.

Limits: It reads saved responses and does not go to the network. A catalogue can be wrong, or describe another edition or a whole set.

  • mismatch

    The source record disagrees with a saved catalogue lookup.

    Why it matters
    A reference with the wrong author, title or year points readers to the wrong work, and is a common sign of an invented or confused citation.
    What to do
    Compare both with the work itself. Correct the record if it is wrong. A catalogue can be wrong or describe another edition: if so, keep the record and the finding shows the difference.
  • no_lookup

    The source's details have not been compared with any catalogue: no lookup that found the work is saved.

    Why it matters
    A reference with the wrong author, title or year points readers to the wrong work, and is a common sign of an invented or confused citation.
    What to do
    Nothing needs doing. `resolve` compares the source once an identifier is known; some works are in no catalogue it reads.
  • lookup_silent

    A saved lookup states no title, so no title could be compared with it.

    Why it matters
    A reference with the wrong author, title or year points readers to the wrong work, and is a common sign of an invented or confused citation.
    What to do
    Nothing needs doing. A lookup by another identifier may state one.
  • set_date

    A saved lookup is for one volume of a set and gives the set's date, and nothing else here shows the volume's year or contradicts it.

    Why it matters
    A reference with the wrong author, title or year points readers to the wrong work, and is a common sign of an invented or confused citation.
    What to do
    Nothing needs doing. A catalogue record that dates the volume, or a copy with a clearer title page text, would corroborate the year.
  • check_error

    The check itself failed while running, so this was not checked.

    Why it matters
    This is a defect in Stemma, not a pass.
    What to do
    Report the defect together with the Stemma version.

Does each identifier lead to the right work? id.resolves

A DOI or library identifier should have a saved catalogue record naming the same work.

What a pass does not tell you: It compares titles. Some kinds of identifier cannot be looked up.

Exact wording: the full description and every message (6)

Each DOI or library identifier on a source record must have a saved lookup that names the same work.

Limits: It compares titles. Only identifiers Stemma can look up are tested; others are reported as not checked.

  • no_lookup

    An identifier on the source record has not been looked up.

    Why it matters
    An identifier that resolves nowhere, or to another work, sends a reader to the wrong thing.
    What to do
    Nothing needs doing. `resolve` looks up DOIs at Crossref and Internet Archive items; other identifiers cannot yet be looked up.
  • not_found

    A catalogue did not find the work this identifier should name.

    Why it matters
    An identifier that resolves nowhere, or to another work, sends a reader to the wrong thing.
    What to do
    Check the identifier against the work and correct or remove it.
  • other_work

    An identifier resolves to a work with a different title.

    Why it matters
    An identifier that resolves nowhere, or to another work, sends a reader to the wrong thing.
    What to do
    Check which is wrong: the identifier or the record's title.
  • lookup_silent

Does your project hold only text? project.binary

Reports binary files, such as Word, PDF or image files, that git tracks or would add. Originals stay outside the project, and their text is converted into it.

What a pass does not tell you: It does not read files git ignores, or earlier history, where a file once added remains.

Exact wording: the full description and every message (1)

The repository must hold no binary file, such as a Word, PDF or image file. It reads the files git tracks or would add.

Limits: A file that git ignores is not read. A file already removed stays in git history, which this does not read.

  • binary_file

    A binary file is in the repository, or would be added to it. A project holds text; originals and other binary files stay outside.

    Why it matters
    git cannot show what changed in a binary, keeps every version for good, and nothing in it can be searched, checked or cited.
    What to do
    Keep the file where the author holds it, outside the repository. To read or cite it, convert it with `source convert`: the Markdown in sources/ is tied to the original by its hash. For a format Stemma does not convert, note what it is, its hash and where it is held. Moving the file out is the author's decision. A file already committed stays in git history until the history is rewritten.

What is not checked

A report runs the checks that apply to what is in your project. These are left to you:

  • Whether the text made from a source matches the pictures of its pages, unless a person compares them.
  • Figures written as words, and whether a figure in a source means what your sentence says.
  • Anything in your manuscript files, which Stemma does not read.

No check tells you whether a source supports your argument, or whether you chose the right source.
