Checks reference

What each check looks at, what a pass does not show, and every finding it can report.

This page is generated from the command line's own explanation texts and from a test run. Outcomes are pass, fail and unverifiable (could not check). No finding blocks anything. A pass covers only what the check says it reads. When a project holds something no check here covers, its report says so, and the project is not called checked clean.

The checks

bib.uncited

Each source listed in bibliography_include must be cited by a citation record.

Limits: It does not read manuscript files. For a project that has them, it reports that it could not check.

An example from the seeded test fixture. The card is this site's drawing of one entry in the JSON report; It is not a Stemma screen.

fail bib.uncited not_cited

A source is listed for the built bibliography but cited nowhere.

Why it matters
The bibliography would list a work the book never cites, or a citation you meant to make is missing.
What to do
Cite it, remove it from bibliography_include in stemma.json, or keep it on purpose and record why.

cite.key

Each citation record's key must name exactly one source record.

Limits: Reads citation records only, not manuscript files. It does not show that a source supports a sentence.

An example from the seeded test fixture. The card is this site's drawing of one entry in the JSON report; It is not a Stemma screen.

fail cite.key key_unknown

A citation uses a key that no source record holds.

Why it matters
A reader or a build cannot tell which source this citation means, so it cannot be checked or put in the bibliography.
What to do
Correct the key in the citation, or add a source record with that key (or add it to the right source's key_aliases).

coordinate.stray

Warns about written map coordinates in project files, without repeating the value.

Limits: Recognizes only geo: addresses, degrees with N, S, E and W, and comma-separated decimal pairs with at least three decimal places. It cannot tell whether a site is restricted.

An example from the seeded test fixture. The card is this site's drawing of one entry in the JSON report; It is not a Stemma screen.

fail coordinate.stray coordinate_text

Text in a project file looks like a map coordinate. The value is not repeated here.

Why it matters
This output can disclose a restricted site's position. The scan cannot tell whether a site is restricted, so it warns about every coordinate it recognizes.
What to do
Look at the position in the evidence. If it is a sensitive site, remove the value from the file (git history may still hold it). If it is public or not a coordinate, you need do nothing.

locator.extent

A citation's page or other locator must fall inside the extent recorded on the source or, for pages and folios, inside the printed pages mapped in your stored copy.

Limits: It tests range only, not that anything is on that page. A page map made from a partial copy covers only that part. It reads citation records only.

quote.present

Each quotation held by a citation record must be in the stored text of the cited source, apart from six harmless differences: white space and line breaks, soft hyphens, Latin ligatures, two Unicode spellings of the same characters, straight against curly quotation marks of the same level, and a word the text splits with a hyphen at a line end. Note extracts and the quoted words of anchored passages are compared too. A close but different passage is shown beside the quotation.

Limits: A pass is agreement with the stored text, which can be wrong, especially where it comes from character recognition. It does not test the cited page, though the text report says when the words were found on another one. Joining a line-end hyphen can pass a quotation that drops a hyphen belonging to the word; the report names each join. Words running across a page break can be missed. It does not read manuscript files.

Reason codeWhat is wrongWhy it mattersWhat to do
near_matchA quotation is not in your stored copy's text as written. A passage close to it is; both are shown.Readers take quoted words to be the source's own. Words the source does not hold misreport it.Compare the two texts, and look at the page itself, since extracted or recognized text can be wrong. If your quotation is wrong, correct it to match the page. An omission, an added word, a change of capitals or punctuation, an ellipsis or a bracketed edit all count as differences.
absentA quotation was not found in your stored copy's text.Readers take quoted words to be the source's own. Words the source does not hold misreport it.Find the words on the page and correct the quotation, or remove the quotation marks if these are your words or a paraphrase. If the page does hold these words, the stored text is wrong there, or it is a different edition: attach a better text or add the copy you quoted. Words that run across a page break can also be missed, because running heads come between them.
text_unavailableA quotation could not be compared: the stored text of its source cannot be used here.Until the quotation can be compared with your copy's text, it is unchecked.See the source.held finding. Add a copy and attach its text, point `--store-dir` at the store that holds it, or restore it from your backup.
poor_qualityA quotation was not found, but the only stored text is marked poor, so this does not show that the source lacks it.Until the quotation can be compared with your copy's text, it is unchecked.Look at the page itself, or attach a better text.
anchor_not_foundA note extract could not be compared: none of the passages it is anchored to can be found in stored text.Until the quotation can be compared with your copy's text, it is unchecked.See the findings on its passages, and anchor the note to a passage that is in the stored text.

record.valid

Reads stemma.json, every record file and the rule headings in rules.md.

Limits: For some record kinds, rules beyond the record shape are not checked. A report says so when such a record is present.

An example from the seeded test fixture. The card is this site's drawing of one entry in the JSON report; It is not a Stemma screen.

unverifiable record.valid record_unreadable

A file cannot be read as a record, so nothing in it was checked.

Why it matters
Every other check reads these files. A broken record can hide a citation problem or create a false one.
What to do
Open the named file and repair it (look for merge-conflict markers, a repeated key or a missing bracket), or restore it from git. Stemma does not guess its content.

source.changed

Lists the notes, claims and citations that rest on a copy, text or source since retired, or on a passage anchored before the source's details changed.

Limits: A citation names no copy, so it is taken to rest on its source's copies and texts retired after the citation was recorded. Stemma cannot yet record that you have looked, so a finding stays listed. A damaged or missing stored file is reported by source.held.

source.held

Each cited source must have a stored copy and extracted text, both in the private content store and both matching their recorded SHA-256 digests.

Limits: It does not show that the text is a faithful reading of the copy: Stemma never compares text with page images. It does not show that a source supports a sentence. It reads citation records only.

An example from the seeded test fixture. The card is this site's drawing of one entry in the JSON report; It is not a Stemma screen.

fail source.held no_copy

A cited source has no stored copy, so this citation is unchecked.

Why it matters
Without a stored copy and its text, nobody can compare this citation with the source, so it is unchecked.
What to do
Add your copy (`source add <file> --source <id>`). For a book you hold only on paper, add a scan and attach its text. Writing can carry on meanwhile.
