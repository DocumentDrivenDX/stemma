What gets checked

Eight checks, what each looks at, and what passing it does not tell you.

Each check answers pass, fail or could not check (the tool writes unverifiable). Nothing is ever blocked. A pass covers only what that check reads. You do not need the names in small type; they are how a report refers to a check.

The checks

  • Do you hold what you cite?
  • Is the quotation in your copy?
  • Is the cited page really there?
  • Which source does this citation mean?
  • Is every listed work cited?
  • Did something you relied on change?
  • Are the project files in order?
  • Is a location written where it should not be?
  • What is not checked

Do you hold what you cite? source.held

Each cited source needs a stored copy and its text, and both must be unchanged since they were saved.

What a pass does not tell you: It does not compare the text with the pictures of the pages, or show that the source supports your sentence.

See an example finding

From a test project with mistakes planted in it. This card is the site's own layout of one entry in a report; it is not a Stemma screen.

fail source.held no_copy

A cited source has no stored copy, so this citation is unchecked.

Why it matters
Without a stored copy and its text, nobody can compare this citation with the source, so it is unchecked.
What to do
Add your copy (`source add <file> --source <id>`). For a book you hold only on paper, add a scan and attach its text. Writing can carry on meanwhile.
  • cit-fixture0good00001
  • citation file: records/citations/cit-fixture0good00001.json
  • key: hartwell1998
  • source file: records/sources/src-fixture0harbour01.json
Exact wording: the full description and every message (9)

Each cited source must have a stored copy and extracted text, both in the private content store and both matching their recorded SHA-256 digests.

Limits: It does not show that the text is a faithful reading of the copy: Stemma never compares text with page images. It does not show that a source supports a sentence. It reads citation records only.

  • no_copy

    A cited source has no stored copy, so this citation is unchecked.

    Why it matters
    Without a stored copy and its text, nobody can compare this citation with the source, so it is unchecked.
    What to do
    Add your copy (`source add <file> --source <id>`). For a book you hold only on paper, add a scan and attach its text. Writing can carry on meanwhile.
  • no_text

    A cited source has a stored copy but no extracted text, so this citation is unchecked.

    Why it matters
    Without a stored copy and its text, nobody can compare this citation with the source, so it is unchecked.
    What to do
    Attach the text (`source text <capture id>`). A plain UTF-8 text copy is read as it is, and a PDF's own text layer is read page by page. For a scan with no text in it, supply recognized text with a form feed after each page (`--text-layer <file>`); Stemma recognizes no characters in page images.
  • record_unreadable

    Whether you hold this cited source could not be checked: at least one capture or extraction record cannot be read.

    Why it matters
    The unreadable file may be the record of the stored copy or of its text.
    What to do
    Repair the unreadable record first (see the record.valid finding), then run `check` again.
  • copy_missing

    A stored copy could not be checked: its file is not in the content store used here.

    Why it matters
    The records describe one exact file. A missing or changed file cannot stand for it, so nothing that depends on it can be checked.
    What to do
    The content store is private and is not part of the repository. Point `--store-dir` at it, restore the file from your backup, or add the same file again. `store verify` lists every missing digest.
  • copy_altered

    A stored copy no longer matches its recorded digest, so it is not treated as the copy that was added.

    Why it matters
    The records describe one exact file. A missing or changed file cannot stand for it, so nothing that depends on it can be checked.
    What to do
    Restore the file from your backup, or add the original file again. If the source itself changed, add it as a new copy.
  • text_missing

    The extracted text of a stored copy could not be checked: it is not in the content store used here.

    Why it matters
    The records describe one exact file. A missing or changed file cannot stand for it, so nothing that depends on it can be checked.
    What to do
    Point `--store-dir` at the store that holds it, or restore it from your backup. `store verify` lists every missing digest.
  • text_altered

    The stored text of a copy no longer matches its recorded digest, so it is not used.

    Why it matters
    The records describe one exact file. A missing or changed file cannot stand for it, so nothing that depends on it can be checked.
    What to do
    Restore the text from your backup, or attach the text again as a new extraction.
  • text_inconsistent

    An extraction record does not fit its stored text (its size or page spans disagree with it), so it is not used.

    Why it matters
    The records describe one exact file. A missing or changed file cannot stand for it, so nothing that depends on it can be checked.
    What to do
    Retire this extraction and attach the text again as a new one. An extraction is never edited.
  • check_error

    The check itself failed while running, so this was not checked.

    Why it matters
    This is a defect in Stemma, not a pass.
    What to do
    Report the defect together with the Stemma version.

Is the quotation in your copy? quote.present

Each recorded quotation is looked for in the source's text. Differences in line breaks and spacing, and a few other quirks of printed and scanned text, are allowed. A close but different passage is shown next to your quotation.

What a pass does not tell you: A pass means agreement with the text taken from your copy, which can be wrong. It does not test the page number you gave, and words that run over onto the next page can be missed.

Exact wording: the full description and every message (6)

Each quotation held by a citation record must be in the stored text of the cited source, apart from six harmless differences: white space and line breaks, soft hyphens, Latin ligatures, two Unicode spellings of the same characters, straight against curly quotation marks of the same level, and a word the text splits with a hyphen at a line end. Note extracts and the quoted words of anchored passages are compared too. A close but different passage is shown beside the quotation.

Limits: A pass is agreement with the stored text, which can be wrong, especially where it comes from character recognition. It does not test the cited page, though the text report says when the words were found on another one. Joining a line-end hyphen can pass a quotation that drops a hyphen belonging to the word; the report names each join. Words running across a page break can be missed. It does not read manuscript files.

  • near_match

    A quotation is not in your stored copy's text as written. A passage close to it is; both are shown.

    Why it matters
    Readers take quoted words to be the source's own. Words the source does not hold misreport it.
    What to do
    Compare the two texts, and look at the page itself, since extracted or recognized text can be wrong. If your quotation is wrong, correct it to match the page. An omission, an added word, a change of capitals or punctuation, an ellipsis or a bracketed edit all count as differences.
  • absent

    A quotation was not found in your stored copy's text.

    Why it matters
    Readers take quoted words to be the source's own. Words the source does not hold misreport it.
    What to do
    Find the words on the page and correct the quotation, or remove the quotation marks if these are your words or a paraphrase. If the page does hold these words, the stored text is wrong there, or it is a different edition: attach a better text or add the copy you quoted. Words that run across a page break can also be missed, because running heads come between them.
  • text_unavailable

    A quotation could not be compared: the stored text of its source cannot be used here.

    Why it matters
    Until the quotation can be compared with your copy's text, it is unchecked.
    What to do
    See the source.held finding. Add a copy and attach its text, point `--store-dir` at the store that holds it, or restore it from your backup.
  • poor_quality

    A quotation was not found, but the only stored text is marked poor, so this does not show that the source lacks it.

    Why it matters
    Until the quotation can be compared with your copy's text, it is unchecked.
    What to do
    Look at the page itself, or attach a better text.
  • anchor_not_found

    A note extract could not be compared: none of the passages it is anchored to can be found in stored text.

    Why it matters
    Until the quotation can be compared with your copy's text, it is unchecked.
    What to do
    See the findings on its passages, and anchor the note to a passage that is in the stored text.
  • check_error

    The check itself failed while running, so this was not checked.

    Why it matters
    This is a defect in Stemma, not a pass.
    What to do
    Report the defect together with the Stemma version.

Is the cited page really there? locator.extent

The page, or other pointer such as a chapter, must fall within what is recorded for the work or, for pages and folios, within the numbered pages of your copy.

What a pass does not tell you: It only tests the range. It does not show that what you describe is on that page.

Exact wording: the full description and every message (7)

A citation's page or other locator must fall inside the extent recorded on the source or, for pages and folios, inside the printed pages mapped in your stored copy.

Limits: It tests range only, not that anything is on that page. A page map made from a partial copy covers only that part. It reads citation records only.

  • outside_extent

    A citation's locator is outside the extent recorded for the work.

    Why it matters
    A page or other locator that is not in the work sends a reader nowhere, and is a common sign of an invented or mistyped citation.
    What to do
    Check the locator against the work and correct it. If the recorded extent is wrong, correct the source record.
  • outside_page_map

    A cited page is outside the printed pages mapped in your stored copy.

    Why it matters
    A page or other locator that is not in the work sends a reader nowhere, and is a common sign of an invented or mistyped citation.
    What to do
    Check the page number against the source and correct it. If the page is right, your copy is partial or its page map leaves that page without a label: look at the page map (`source pages` proposes one).
  • page_not_mapped

    A cited page falls between mapped pages, on a page the page map gives no label, so it could not be checked.

    Why it matters
    Until the locator can be compared with the work's pages or extent, a wrong one would go unnoticed.
    What to do
    Look at the page in your copy. If its number can be established, attach the text again with a page map that includes it and says what shows the label.
  • no_extent

    A locator could not be checked: no extent is recorded for it, and no page map covers its numbering.

    Why it matters
    Until the locator can be compared with the work's pages or extent, a wrong one would go unnoticed.
    What to do
    For pages, attach your copy's text with a page map (`source pages` proposes one from the printed numbers). For another kind of locator, record the work's extent on the source, taken from the work itself.
  • unparsable_locator

    A locator is not written in a form that can be compared with the work's pages or extent.

    Why it matters
    Until the locator can be compared with the work's pages or extent, a wrong one would go unnoticed.
    What to do
    Write it as the printed label, or as a range with both ends in full, such as 41-43. Otherwise check it by hand.
  • record_unreadable

    A locator could not be checked: at least one capture or extraction record cannot be read.

    Why it matters
    Until the locator can be compared with the work's pages or extent, a wrong one would go unnoticed.
    What to do
    Repair the unreadable record first (see the record.valid finding), then run `check` again.
  • check_error

    The check itself failed while running, so this was not checked.

    Why it matters
    This is a defect in Stemma, not a pass.
    What to do
    Report the defect together with the Stemma version.

Which source does this citation mean? cite.key

The short label in each citation must match exactly one source.

What a pass does not tell you: It reads recorded citations, not your manuscript, and does not show that the source supports your sentence.

fail cite.key key_unknown

A citation uses a key that no source record holds.

Why it matters
A reader or a build cannot tell which source this citation means, so it cannot be checked or put in the bibliography.
What to do
Correct the key in the citation, or add a source record with that key (or add it to the right source's key_aliases).

Exact wording: the full description and every message (5)

Each citation record's key must name exactly one source record.

Limits: Reads citation records only, not manuscript files. It does not show that a source supports a sentence.

  • key_unknown

    A citation uses a key that no source record holds.

    Why it matters
    A reader or a build cannot tell which source this citation means, so it cannot be checked or put in the bibliography.
    What to do

  • key_ambiguous

    A citation uses a key that more than one source record holds.

    Why it matters
    A reader or a build cannot tell which source this citation means, so it cannot be checked or put in the bibliography.

  • key_missing

    Why it matters
    A reader or a build cannot tell which source this citation means, so it cannot be checked or put in the bibliography.
    What to do
    Add the key of the source being cited, or remove the citation.
  • source_unreadable

    Why it matters
    The unreadable file may or may not be the source this citation means.
    What to do

Is every listed work cited? bib.uncited

A work you have listed for the bibliography should be cited somewhere.

What a pass does not tell you: It cannot tell when your project has manuscript files, because it does not read them. It says so.

fail bib.uncited not_cited

A source is listed for the built bibliography but cited nowhere.

Why it matters
The bibliography would list a work the book never cites, or a citation you meant to make is missing.
What to do
Cite it, remove it from bibliography_include in stemma.json, or keep it on purpose and record why.

Limits: It does not read manuscript files. For a project that has them, it reports that it could not check.

Did something you relied on change? source.changed

Lists citations and other work that rest on a copy, text or source you have since replaced or set aside.

What a pass does not tell you: It cannot record that you have looked again, so an item stays listed. Missing or altered files are reported by the first check.

Exact wording: the full description and every message (4)

Lists the notes, claims and citations that rest on a copy, text or source since retired, or on a passage anchored before the source's details changed.

Limits: A citation names no copy, so it is taken to rest on its source's copies and texts retired after the citation was recorded. Stemma cannot yet record that you have looked, so a finding stays listed. A damaged or missing stored file is reported by source.held.

  • depends_on_retired

    This rests on a copy, text or source that has since been replaced or retired.

    Why it matters
    What you read, quoted or relied on may differ in what replaced it, so it needs looking at again.
    What to do
    Compare what you took from it with what replaced it, then correct or retire this item if it no longer holds. Stemma cannot yet record that you have looked, so the finding stays listed.
  • source_details_changed

    The source's details changed after a passage this rests on was anchored.

    Why it matters
    What you read, quoted or relied on may differ in what replaced it, so it needs looking at again.
    What to do
    Check that the passage still belongs to the source as it is now recorded. Anchor it again as a new passage if it does.
  • record_unreadable

    Whether what this rests on has changed could not be checked: a record it depends on cannot be read.

    Why it matters
    What you read, quoted or relied on may differ in what replaced it, so it needs looking at again.
    What to do
    Repair the unreadable record first (see the record.valid finding), then run `check` again.
  • check_error

    The check itself failed while running, so this was not checked.

    Why it matters
    This is a defect in Stemma, not a pass.
    What to do
    Report the defect together with the Stemma version.

Are the project files in order? record.valid

Reads the settings, every record and the headings of your standing rules.

What a pass does not tell you: Some kinds of record are only partly checked. The report says when your project has one.

See an example finding

From a test project with mistakes planted in it. This card is the site's own layout of one entry in a report; it is not a Stemma screen.

unverifiable record.valid record_unreadable

A file cannot be read as a record, so nothing in it was checked.

Why it matters
Every other check reads these files. A broken record can hide a citation problem or create a false one.
What to do
Open the named file and repair it (look for merge-conflict markers, a repeated key or a missing bracket), or restore it from git. Stemma does not guess its content.
  • records/agents/agt-fixture0broken001.json
  • file: records/agents/agt-fixture0broken001.json
  • problem: duplicate_key
Exact wording: the full description and every message (10)

Reads stemma.json, every record file and the rule headings in rules.md.

Limits: For some record kinds, rules beyond the record shape are not checked. A report says so when such a record is present.

  • record_unreadable

    A file cannot be read as a record, so nothing in it was checked.

    Why it matters
    Every other check reads these files. A broken record can hide a citation problem or create a false one.
    What to do
    Open the named file and repair it (look for merge-conflict markers, a repeated key or a missing bracket), or restore it from git. Stemma does not guess its content.
  • version_unsupported

    A file was written in a newer record format than this version reads, so it was not checked.

    Why it matters
    Every other check reads these files. A broken record can hide a citation problem or create a false one.
    What to do
    Update Stemma before changing this file. This version will not rewrite it.
  • record_noncanonical

    A file is not written in the canonical form (key order, indentation or line endings differ).

    Why it matters
    Digests, review marks and diffs depend on one exact form. No value is wrong because of this alone.
    What to do
    Run `fmt` on the file. It rewrites the layout and changes no value.
  • record_invalid

    A record breaks a rule of the record format.

    Why it matters
    Every other check reads these files. A broken record can hide a citation problem or create a false one.
    What to do
    Correct the field named in the evidence, then run `check` again.
  • record_misplaced

    A file under records/ is not where its record belongs (file name or directory does not match).

    Why it matters
    References and tools find records by ID, directory and file name.
    What to do
    Rename or move the file as the evidence shows, or move a file that is not a record out of records/.
  • reference_dangling

    A record points at a record that is missing or is of the wrong kind.

    Why it matters
    The link between your evidence and its source is broken, so anything relying on it cannot be traced.
    What to do
    Point the reference at the right record, or remove it.
  • unknown_field

    A record has a field the record format does not define. The field is kept as it is.

    Why it matters
    A misspelled field name means the value you meant to record is not read.
    What to do
    Check the spelling. Put a field of your own under `x` with a namespaced name such as `myname.note`.
  • rule_heading_invalid

    A heading in rules.md is not a rule heading.

    Why it matters
    Reports and records cite standing rules by ID, so a rule without one cannot be cited.
    What to do
    Write each rule heading as `## RULE-001 Title`.
  • rule_id_duplicate

    A rule ID in rules.md is used twice.

    Why it matters
    A report or record citing this ID could mean either rule.
    What to do
    Give the later rule a number that has never been used.
  • check_error

    The check itself failed while running, so this was not checked.

    Why it matters
    This is a defect in Stemma, not a pass.
    What to do
    Report the defect together with the Stemma version.

Is a location written where it should not be? coordinate.stray

Warns about map coordinates written in project files, without repeating them.

What a pass does not tell you: It only recognizes some ways of writing coordinates, and cannot tell whether a place is sensitive.

See an example finding

From a test project with mistakes planted in it. This card is the site's own layout of one entry in a report; it is not a Stemma screen.

fail coordinate.stray coordinate_text

Text in a project file looks like a map coordinate. The value is not repeated here.

Why it matters
This output can disclose a restricted site's position. The scan cannot tell whether a site is restricted, so it warns about every coordinate it recognizes.
What to do
Look at the position in the evidence. If it is a sensitive site, remove the value from the file (git history may still hold it). If it is public or not a coordinate, you need do nothing.

  • position: line 5, column 27

Warns about written map coordinates in project files, without repeating the value.

Limits: Recognizes only geo: addresses, degrees with N, S, E and W, and comma-separated decimal pairs with at least three decimal places. It cannot tell whether a site is restricted.

What is not checked

When your project has something these would apply to, the report lists them, and the project is not called checked clean. Check these yourself where they matter:

  • Authors, titles and dates, against library catalogues or against your copies.
  • Whether identifiers such as DOIs lead to the works you mean.
  • Whether figures and statistics you cite appear in the source.
  • Anything in your manuscript files, which Stemma does not read.

No check tells you whether a source supports your argument, or whether you chose the right source.
